DRX

Reactive web apps, written in markup.

DRX (Declarative Reactive X) is a declarative markup language powered by Vorplex. Compose your app with <x-*> tags, then use ordinary HTML for its interface.

Quick Start

Save this example as an HTML file and open it in a browser. The script loads DRX, <x-app> wraps the application, and <x-page> defines its first view. No build configuration is needed.

App

The composition root for your application.

Use exactly one <x-app>. It contains your pages and app-level declarations, such as shared variables, types, services, and components. Pages can access App variables; components cannot.

Variables

Read and write state through callable signals.

Use no arguments to read a signal, and one argument to write it. The variable body holds the initial data, not a schema.

<x-variable>

Attribute Description
name The variable's identifier.
type? TSON type; defaults to any.
property? is optional. *property supports {{ }} expressions;

Placement and Scope

<x-variable> can only be a direct child of <x-app>, <x-page>, or <x-component>. Do not put it inside an HTML element, a control-flow tag, or a service.

Pages can access their own variables and App variables. Components can access only their own variables, not those of the App, a page, or an enclosing component.

profile.name() subscribes only to that path. profile().name subscribes to the whole object and reruns on any change to it. Path traversal is null-safe: an unset intermediate value reads as undefined.

Expressions

Bind the parts of ordinary HTML that change.

{{ }} expressions work in text and element attributes, including <x-icon> attributes. Event handlers are plain calls, not expressions wrapped in braces.

Syntax Behavior
{{value()}} Interpolate a value into text or an attribute.
class.<name> Toggle a class according to truthiness.
style.<property> Set one inline style property.
onclick="method()" Call a script method or a signal once per event; not reactively tracked.

Components

A fully isolated piece of your interface.

A component can access only its own variables, declared directly inside <x-component>. It cannot access variables from the App, a page, or an enclosing component. Declare its other dependencies locally too, including assets, APIs, and nested components. Properties bring data in; events send data out.

Modals

Open a page and await the value it returns.

Any page can open with drx.pages.<name>.showModal({ data }). Its data is available from onMount() onward as drx.modal.data in scripts and modal.data in templates. Close it with drx.modal.close(value) or modal.close(value).

DRX supplies a bare full-screen host. The page owns its backdrop, centering, and sizing.

TSON

Schemas describe data. Variables hold it.

The type attribute on <x-variable>, <x-property>, <x-event>, <x-body>, and <x-response> accepts a primitive type name or a named <x-type>. TSON is DRX's schema notation.

Type Extra Keys Schema
string min, max, match (regex) { "type": "string", "min": 1, "max": 40 }
number min, max, integer { "type": "number", "integer": true, "min": 0 }
boolean None { "type": "boolean" }
object properties { "type": "object", "properties": { "name": { "type": "string" } } }
array itemDefinition, min, max { "type": "array", "itemDefinition": { "type": "string" } }
enum flags (required) { "type": "enum", "flags": ["success", "warning", "error"] }
record property { "type": "record", "property": { "type": "boolean" } }
union union (array of types) { "type": "union", "union": [{ "type": "string" }, { "type": "number" }] }
any None { "type": "any" }

Records and Unions

A record allows arbitrary string keys sharing one value type. A union accepts a value matching one of its listed types.
